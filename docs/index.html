01 — Features

One output shape. Zero surprises.

Every command prints the same four parts — summary, risk, recommendation, detail — so you can scan fast or pipe it to tooling.

Know where you stand

sg status turns branch position, working tree, and next actions into plain language. sg doctor goes deeper and reports object, HEAD, and tree health signals.

sg statussg doctorsg check

AI help, only where it pays

sg explain turns diffs into intent. sg commit drafts the message and asks before it writes. OpenAI, Anthropic, Gemini, Mistral, or your own endpoint.

sg explainsg commit

Push without fear

sg push checks divergence, conflicts, and hosted signals first. sg check scores merge risk against your target branch.

sg pushsg check

Recover with a guide

sg fix walks conflicts, detached HEAD, and stalled rebases step by step. sg wtf triages first — add --learn or --fix-ci when you need them.

sg fixsg wtfsg undo

Ship and reshape history

sg sync preserves local work while you update. sg ship runs delivery end to end, sg split groups staged changes, sg time-travel resolves refs — plain words included.

sg syncsg shipsg split

Team context, hosted context

sg who, sg queue --team, and sg blame --explain pair local ownership with GitHub signals when gh is present. sg pair keeps handoffs short.

sg whosg queuesg blame

Works with no AI at all

Rule-based fallbacks carry every command that does not strictly need a model. AI-only commands exit with a clear message instead of a guess.

offline-safesg ai-configure
02 — Commands

Nineteen commands. One binary.

Install the sanegit package globally, then run everything as sg <command>. Type to filter.

CORE LOOPDaily state, change review, and publish checks.
sg status

Plain-English repository state and recommended next action.

sg explain

Explain current changes (requires AI).

sg commit

Proposed commit from staged files; confirms before git commit (requires AI).

sg push

Pre-push risk checks and safer publish flow.

sg check

Merge and integration readiness vs. a target branch.

RECOVERYBroken states, rollbacks, and urgent triage.
sg fix

Guided recovery from common broken git states.

sg undo

List reversible rollbacks with explicit consequences.

sg wtf

Urgent diagnosis; --learn, --fix-ci.

SHIPSync, deliver, split, and move through history.
sg sync

Preserve local work while updating from mainline.

sg ship

One-command delivery; use sg ship --status for workflow state.

sg split

Propose logical commit groups from staged changes.

sg time-travel --to <ref>

Resolve revisions safely, including natural-language references.

TEAM + HOSTINGOwnership, queue, blame, and pair work.
sg who [--file <path>]

Ownership and collaborator context; path may be a file or directory.

sg queue --team

Merge queue visibility and risk hints.

sg blame --file <path> --line <n> --explain

Line history with rationale (hosted context when available).

sg pair --action <start|status|handoff>

Pair sessions; use --session with status and handoff.

SETUPHealth signals and provider setup.
sg doctor

Deep repository health signals (HEAD, objects, working tree, etc.).

sg ai-configure

Set provider, --credential-ref, optional --url for custom APIs.

sg resolve

Structured conflict triage with safe, confirmable steps.

03 — Workflow

A loop you can run half asleep.

Stay in rule-based commands, add AI only where it helps, and use hosted signals when gh is around.

1

Orient

Run sg status after you switch branches or pull.

2

Review

sg explain for intent, sg check before a big merge.

3

Commit

Stage files, then sg commit or commit by hand.

4

Publish

sg push or sg ship; track with sg ship --status.

5

Recover

sg wtf first, then sg fix or sg undo.

04 — Install

Runs on Node 22 and git. That is it.

SaneGit ships as an npm package. GitHub CLI (gh) is optional and adds richer hosted context.

From npm

Global CLI$ npm install -g sanegit

From source

$ git clone https://github.com/ntufar/sanegit.git
$ cd sanegit && npm install
$ npm run build && npm link

Configure AI (optional)

Settings live in .sanegit/ — keep that directory local and gitignored. Keys never touch config files: pass a credential reference and it resolves at runtime.

$ sg ai-configure --provider openai --credential-ref OPENAI_API_KEY
!

AI-required commands

sg explain and sg commit need a working provider. The rest run on rules, hosted APIs, or local git data.

05 — Quick start

Inside any repo, in under a minute.

01 · Check health

$ cd my-repo && sg status

02 · Explain and commit (with AI)

$ git add src/feature.ts
$ sg explain
$ sg commit

03 · Ship or push

$ sg push # or the full flow
$ sg ship
$ sg ship --status

04 · When it breaks

$ sg wtf # triage first
$ sg fix # then guided repair
